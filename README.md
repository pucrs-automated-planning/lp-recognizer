## Quick Start

> [!NOTE]
> This assumes you have IBM CPLEX installed and licensed (required to reproduce the paper results), or are comfortable obtaining a working Fast Downward build with an LP solver. See the [Installation](#installation) section for details.

```bash
git clone https://github.com/pucrs-automated-planning/lp-recognizer.git
cd lp-recognizer

# 1. Build Fast Downward with CPLEX
export cplex_DIR=/path/to/CPLEX_Studio<ver>/cplex
bash prepare-fd.sh

# 2. Download the dataset
cd experiments && bash get_datasets.sh && cd ..

# 3. Run all paper experiments (takes a long time)
cd experiments && ./get_results.sh -rerun
```

Results land in `outputs/` (raw), `data-tables/` (LaTeX fragments), and `data-comparison/` (comparison tables).

## Installation

LP-Recognizer is written mostly in Python, but we rely heavily on the constraints generated by the heuristic functions in the [Fast Downward](http://www.fast-downward.org) planner, so configuration is a two-step process.

1. Install an LP solver — either the free [SoPlex](https://soplex.zib.de) or commercial [IBM CPLEX](https://www.ibm.com/products/ilog-cplex-optimization-studio) (required to enable the OperatorCounting heuristic plugin in Fast Downward).
2. Download, patch, and build Fast Downward using the provided script.

> [!WARNING]
> The results in the AAAI 2021 paper were obtained using IBM CPLEX. When using SoPlex, the `flow_constraints(systematic(2))` heuristic returns `SEARCH_UNSUPPORTED`, so recognizers relying on that configuration will not reproduce the paper results. All other heuristics (`lmcut_constraints`, `delete_relaxation_constraints`, `state_equation_constraints`, `pho_constraints`) work correctly with SoPlex.

We provide automated scripts for both steps. For SoPlex (no sign-up required):

```bash
git clone https://github.com/pucrs-automated-planning/lp-recognizer.git
cd lp-recognizer
bash install-soplex.sh          # builds SoPlex into ~/.local/soplex
export soplex_DIR="$HOME/.local/soplex"
bash prepare-fd.sh              # downloads Fast Downward, applies patches, compiles
```

To use IBM CPLEX instead, install it separately and export `cplex_DIR` pointing to the `cplex/` subdirectory of your installation before running `prepare-fd.sh`:

```bash
export cplex_DIR=/path/to/CPLEX_Studio<ver>/cplex   # e.g. ~/Applications/CPLEX_Studio2212/cplex
bash prepare-fd.sh
```

Both solvers can be compiled in simultaneously by exporting both variables.

## Running LP-Recognizer

### Running plan recognition in a single problem

We base our Python code off of Ramirez and Geffner's original recognizer, so experiments are in the form of a ```tar.bz2``` file containing:

- A PDDL Domain
- An observation sequence
- A number of hypotheses (possible goal formulas)
- A PDDL Problem Template (containing the initial state)

This recognizer is compatible with all the domains in this publicly available dataset of [Goal and Plan Recognition Datasets](https://github.com/pucrs-automated-planning/goal-plan-recognition-dataset-lp). We currently implement three different approaches to goal recognition based on operator counts:

1. Comparing overlap of observations and operator counts, accessible with the ```hvalue``` heuristic
2. Minimizing the operator counts subject to constraints derived from the observations (i.e. all observations must be included in the counts), accessible with the ```hvaluec``` and ```hvaluecu``` (measuring uncertainty) heuristics
3. Minimizing the difference between the operator counts with the observation constraints and the operator counts with then, accessible with the ```delta``` and ```deltau``` (measuring uncertainty) heuristics

It is also possible to add parameters in the heuristic name:

1. Using noisy filters by adding ```-f``` followed by a number x that means 0.x of noise. Example: ```delta-f2``` for 20% of noise
2. Change the constraint sets by adding ```-c``` followed by ```l``` (landmarks), ```s``` (state equation), ```p``` (post-hoc), or combations. Example: ```delta-clp``` for landmarks with post-hoc constraints
3. Use IP instead of LP by adding ```-i```. Example: ```delta-i-cs``` for IP using only state equation constraints

To run any experiment, just run:

```bash
python test_instance.py -r <heuristics> -e <experiment_file>
```

where ```<experiment_file>``` is one of the experiments in your dataset.
For example, with the experiments we provide here, we could run Sokoban with the hard-constraints strategy as follows:

```bash
./test_instance.py -r delta -e experiments/small-sokoban-optimal/10/sokoban_p01_hyp-1_10_1.tar.bz2
```

### Running plan recognition in a set of experiments

In order to run experiments for an entire domain organized in a folder named ```domain```, you need to run:

```bash
./test_domain.py <path> <domain> <heuristics>
```

For example, to run the sokoban sample using all the heuristics, you need to run:

```bash
./test_domain.py "experiments/" small-sokoban-optimal "delta deltau delta-f2"
```

### Running paper experiments locally

The full experiments from both the AAAI 2021 and JAIR papers require the dataset to be cloned as a sibling of this repository first:

```bash
cd experiments && bash get_datasets.sh
```

This clones [goal-plan-recognition-dataset-lp](https://github.com/pucrs-automated-planning/goal-plan-recognition-dataset-lp) into `../goal-plan-recognition-dataset/`. Then run all methods across all 12 domains:

```bash
cd experiments && ./get_results.sh -rerun
```

This runs the LMC methods (`delta-cl`, `delta-o-cl`, `delta-o-cl3`, `delta-o-cl1`) for the AAAI 2021 paper followed by the DELR methods (`delta-cdt`, `delta-o-cdto`, `delta-o-cdtb5`, `delta-o1-cdtb5`) for the JAIR paper, over all 12 domains at 5 observability levels. Since the dataset is large, this takes a very long time.

Results are written to the following directories (all relative to the repository root):

| Directory | Contents |
| --- | --- |
| `outputs/` | One `.output` file per `(domain-type, method)` with raw recognizer results |
| `data-tables/` | Per-domain LaTeX table fragments, one per `(domain-type, method)` |
| `data-charts/` | Chart data files used by the LaTeX chart scripts |
| `data-comparison/` | Cross-domain comparison tables (generated with `-comp`) |
| `latex-tables/` | Compiled PDF tables (generated with `-comp`) |

To regenerate tables from existing `.output` files without rerunning experiments:

```bash
cd experiments && ./get_results.sh -txt           # regenerate data-tables/ only
cd experiments && ./get_results.sh -txt -comp     # also regenerate data-comparison/ and latex-tables/
```

### Running experiments on an HPC cluster (Slurm)

We provide Slurm scripts in the [slurm/](slurm/) directory. These require [goal-plan-recognition-dataset-lp](https://github.com/pucrs-automated-planning/goal-plan-recognition-dataset-lp) to be cloned as a sibling of this repository at `../goal-plan-recognition-dataset/`, which `experiments/get_datasets.sh` does automatically.

#### Sequential baseline

Submits a single job that runs `get_results.sh -rerun` end-to-end, equivalent to running it locally:

```bash
bash slurm/run_get_results.sh           # all 12 domains
bash slurm/run_get_results.sh -fast     # 6-domain subset
```

The partition is detected automatically from `sinfo`. Override with `--partition <name>` if needed.

#### Parallel array job

Submits one Slurm array job per recognizer method. Each array has 120 tasks (12 domains × 2 dataset types × 5 observability levels), running all instances for one domain/type/observability combination per task. Results accumulate under `slurm-results/` and are safe to resume after interruption — completed instances are skipped automatically.

```bash
bash slurm/submit_jobs.sh                       # all 16 methods (LMC + DELR)
bash slurm/submit_jobs.sh --fast                # 6-domain subset
bash slurm/submit_jobs.sh --method delta-cdt    # single method
```

Once all jobs finish, collect results and regenerate tables:

```bash
bash slurm/collect_results.sh --check   # verify no missing results
bash slurm/collect_results.sh           # merge outputs/ + regenerate data-tables/
bash slurm/collect_results.sh --latex   # also generate data-comparison/ and chart data
```

The same output directories as the local run apply (`outputs/`, `data-tables/`, `data-charts/`, `data-comparison/`).

To rerun experiments, clean existing results first with `slurm/clean_results.sh`:

```bash
bash slurm/clean_results.sh --partial            # remove empty/truncated files (job killed mid-write)
bash slurm/clean_results.sh --method delta-cdt   # remove all results for one method
bash slurm/clean_results.sh --domain blocks-world-optimal  # remove all results for one domain-type
bash slurm/clean_results.sh --all                # remove everything under slurm-results/
```

Alternatively, pass `--force` to `submit_jobs.sh` to overwrite existing results without deleting them first:

```bash
bash slurm/submit_jobs.sh --force
bash slurm/submit_jobs.sh --force --method delta-cdt
```

## Patches to Fast Downward here

We store our changes to Fast Downward in the ```fd-patch.diff``` patch file in this repository. Whenever you change Fast Downward for LP-Recognizer, ensure these changes are stored here by running:

```bash
bash make-fd-patch.sh
git commit -m "Storing patches to Fast Downward" fd-patch.diff fd-patch-rev.txt
git push
```
